# Checkpoint 9.4C-B — diccionario físico PostgreSQL

**Estado:** CANDIDATO V2; diseño, no implementado ni congelado. **Corte:** 2026-10-09.
**Autoridad lógica:** [catálogo](../logical/entity-catalog.md), [relaciones](../logical/relationship-matrix.md), [restricciones](../logical/constraint-matrix.md), [normalización](../normalization/9.4C-A-review.md). La baseline se conserva desde la [revisión V1.1 fijada](../../baseline-v1.1/README.md).

## Convenciones físicas

- Nombres baseline entre comillas conservan exactamente tabla/columna Prisma V1.1. Nuevas tablas/columnas usan `snake_case`; futuro Prisma deberá usar `@@map`/`@map`. Ningún rename baseline forma parte de este checkpoint.
- `i4` = `integer`; PK autogenerada baseline conserva secuencia existente y PK nueva usa `integer GENERATED BY DEFAULT AS IDENTITY`; `txt` = `text`; `vN` = `varchar(N)`; `bool` = `boolean`; `ts` = `timestamp(3) without time zone`; `date` = `date`; `num(p,s)` = `numeric(p,s)`; `json` = `jsonb`; `enum(X)` = enum PostgreSQL respaldado por enum Prisma. `command_key:v128` usa comparación binaria estable (`COLLATE "C"`) y no se normaliza ni cambia después del insert.
- `?` = nullable; sin `?` = `NOT NULL`; `=x` = default. `createdAt=now`, `updatedAt=now` son defaults físicos candidatos; semántica `@updatedAt` sigue siendo Prisma/servicio, no default de actualización PostgreSQL.
- Dinero: `numeric(14,2)` y código de moneda `text` baseline; V2 nuevo `char(3)`. Cantidades fraccionables físicas: `numeric(14,3)`; cantidades de préstamos baseline siguen `integer`. Checks y acciones FK: [restricciones físicas](postgresql-constraints.md).
- Campos `status`, `result`, `condition`, `type` nuevos usan `varchar(32)` mientras su vocabulario no esté confirmado; no se inventan enums. Valores ya validados sí pueden convertirse a enum durante 9.4C-C.

**Refinamiento físico de idempotencia F-02:** las tres tablas de decisión incorporan `command_key varchar(128) COLLATE "C" NOT NULL` con UQ global dentro de su tabla. Alcance de clave es tipo de comando/tabla; valor opaco identifica intención lógica emitida por cliente/servicio, no padre ni resultado. Repetir misma clave relee misma decisión; nueva decisión legítima para mismo padre usa clave distinta. No existe UQ por padre, `(padre,membership)` ni estado: cardinalidad institucional 1:N permanece. Refinamiento suma exactamente **3 columnas** y **3 CK/UQ firmes**, sin tabla nueva ni decisión institucional.
